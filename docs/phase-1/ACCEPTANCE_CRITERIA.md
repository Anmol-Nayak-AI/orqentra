# Acceptance criteria

Status: proposed, not executed. These criteria define future verification; none are claims of achieved security, reliability, performance or production readiness. Phase 1 completion is document completeness and consistency only.

## Test environment and evidence

Use the pinned full stack with real PostgreSQL/pgvector, restricted runtime roles, official Postgres-backed checkpoints, Redis, a fixture identity provider, deterministic structured inference fixtures, a synthetic knowledge corpus, and a local simulated delivery adapter. No live delivery credentials. Use two organizations with two workspaces each, overlapping display names and distinct records, multiple user roles, and a revoked user. Model quality tests later use an explicitly approved provider and deidentified corpus.

Every criterion result must include commit/lockfile identifiers, command, environment, fixture version, timestamp, actual output/report, and relevant audit/action counts. “Pass” requires actual execution. Assertions below are necessary design targets, not proof that all vulnerabilities or failure modes have been eliminated. Pytest owns domain/integration/security/fault verification; Vitest owns UI state behavior; Playwright owns full browser journeys.

## Browser journey acceptance

An operator can sign in, select an authorized workspace, submit a request, view run/step progress and evidence, and reload without losing state. A distinct eligible reviewer sees the exact bundle, approves it once, and sees a clearly simulated receipt. Missing facts create an actionable task; rejected, expired, denied, cancelled, failed and budget-exceeded states explain the next permitted action. Evidence drawers display source title/location/status without executing source HTML. Forms and review controls work with keyboard navigation and accessible labels. Test loading, reconnect and empty states; never show a transient false “sent” status.

## Business evaluation protocol

Before pilot, agree a deidentified/synthetic labeled case set including normal, incomplete, contradictory, duplicate, missing-source, malicious-source and provider-failure requests. Version dataset, rubric, model, prompts, pricing and scorers. Report evidence support, completeness, unsafe-action count, cost and latency by case type; include human agreement and disagreements for semantic scoring. Proposed ≥80% first-review acceptance and ≥30% reduction in handling time are hypotheses measured against a manual baseline, not CI assertions or achieved metrics. No live customer communication is needed for this evaluation.
