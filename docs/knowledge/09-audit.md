# Orqentra guide · Audit trail and troubleshooting
Audit trail is the organization's read-only history of recorded changes. It helps explain what happened and when. Search by event or resource ID, filter categories and expand Event details for identifiers and timestamps. It is an activity record, not the chat conversation screen.

A historical chat failure can remain visible after a retry succeeds. When the same resource has a later completion, the page identifies it as recovered. Keeping the old event preserves the history; it does not mean that the current chat is failing. Read the answer in Chat.

If a chat reply is unavailable, check that the right workspace is selected and the relevant Knowledge index is READY. Add a source for undocumented facts, retry transient errors, or request human help. A lack-of-evidence reply means the selected sources do not support the answer; it is not permission to invent one. If a request fails, preserve the visible Request ID for an administrator and do not send credentials. The assistant can explain documented troubleshooting steps but cannot diagnose unseen live sessions with certainty.
